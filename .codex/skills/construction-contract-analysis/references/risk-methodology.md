# 风险方法论与安全护栏

> 本文件定义施工合同分析中的统一风险评价方法论、来源溯源标签体系和安全护栏规则。
> 所有分析模块（module-1 至 module-8）均须遵循本文件定义的标准。

---

## 一、来源溯源标签体系

所有法律引用和事实陈述必须标注来源类型。标签分为三级：

### 1.1 三级标签定义

| 标签 | 含义 | 适用场景 |
|------|------|----------|
| `[法条原文]` | 直接引用的法律法规条文原文 | 民法典/司法解释/行政法规的具体条文 |
| `[司法解释]` | 最高人民法院司法解释或批复 | 建设工程司法解释一/二、证据规定等 |
| `[裁判规则]` | 裁判文书提炼的裁判规则或司法实践共识 | 最高法公报案例、指导案例、类案检索结论 |

### 1.2 附加验证标签

| 标签 | 含义 |
|------|------|
| `[已核实]` | 当前会话中已通过检索工具独立核实 |
| `[需验证]` | 来源于模型训练数据，未在本次会话中独立检索核实 |
| `[合同原文]` | 摘录自用户上传的合同文件 |
| `[用户陈述]` | 来源于用户口述的履约事实，非客观证据 | v2.0 |
| `[OCR提取]` | 通过 MinerU OCR/pdfplumber 从扫描件提取的文字，原件未核实 | v2.0 |
| `[模板]` | 依据的是招标文件嵌入的合同模板，非实际签署版本 | v2.0 |

### 1.3 使用规范

1. 每条法律主张必须附带至少一个来源标签
2. 关键法条必须同时标注 `[法条原文]` + `[已核实]` 或 `[需验证]`
3. 未连接检索工具时，所有引用统一标注 `[需验证]`，不得省略
4. 合同条款分析必须标注 `[合同原文]` + 页码/条款号
5. `[OCR提取]` 标签必须配合核验等级（Level 1/2/3）使用，详见 `ocr-verification-protocol.md` ★v2.0
6. `[模板]` 标签用于区分招标文件嵌入模板与实际签署版本 ★v2.0

**格式示例**：
```
根据《民法典》第807条，发包人未按照约定支付价款的，承包人可就建设工程主张优先受偿权。
`[法条原文]` `[需验证]`
```

## 二、六维风险评价方法论

### 2.1 六个评价维度

对施工合同每一条款和每一争议点，从六个维度系统评估：

| 维度 | 评估内容 | 评级 |
|------|---------|------|
| **风险定性** | 该风险的法律性质——权利丧失/义务加重/责任豁免/程序障碍/证据困难/财务敞口 | 用6类标签标注 |
| **敞口规模** | 可能的经济损失金额或比例范围 | 具体金额或合同价百分比区间 |
| **发生概率** | 在当前合同约定和履约事实下发生的可能性 | 高/中/低 |
| **可规避性** | 是否可通过合同修订、补充协议、履约行为改变来规避或降低 | 可规避/可降低/不可规避 |
| **商业权衡** | 该风险点的商业合理性——是否为行业惯例、是否被对方商业谈判中坚持 | 行业惯例/商业合理/异常苛刻 |
| **紧迫性** | 是否需要立即行动（如时效即将届满、财产即将转移、证据即将灭失） | 紧急(7天内)/优先(30天内)/常规/监控 |

### 2.2 风险定性六类标签

| 风险定性 | 含义 | 施工合同典型场景 |
|---------|------|----------------|
| 权利丧失 | 当事人可能丧失实体或程序权利 | 优先受偿权过期、调价申报超期、索赔逾期失权 |
| 义务加重 | 一方承担超出法定或行业惯例的义务 | 无限期质保、过分严苛的验收标准、不合理的审计前置 |
| 责任豁免 | 一方不合理地免除或限制自身责任 | 发包人免除提供施工条件责任、承包人免除质量责任 |
| 程序障碍 | 程序设置增加维权难度 | 苛刻的通知时限、多级争议前置程序 |
| 证据困难 | 举证责任分配或证据获取存在困难 | 隐蔽工程验收无记录、签证口头确认无书面 |
| 财务敞口 | 直接或间接的财务损失风险 | 垫资无利息约定、质保金返还条件模糊、违约金过高 |

### 2.3 应用示例

```
条款：C4 违约责任条款
原文摘录："承包人逾期竣工的，每逾期一日按合同总价的千分之一支付违约金，上不封顶。"

六维评价：
| 维度 | 评估 |
|------|------|
| 风险定性 | 财务敞口（违约金上不封顶） |
| 敞口规模 | 日千分之一 ≈ 年化36.5%，远超司法调整上限 |
| 发生概率 | 中（工期延误在施工中常见） |
| 可规避性 | 可降低（协商增设违约金上限，建议不超过合同价5%） |
| 商业权衡 | 异常苛刻（行业通常约定万分之三至万分之五） |
| 紧迫性 | 优先（应在签约前或纠纷前协商调整） |
```

## 三、双轴严重性标尺

### 3.1 双轴定义

每个风险点同时在两个轴向上评估严重性：

**法律风险轴**：违约/违法/失权的法律后果严重程度
- 低：轻微程序瑕疵，不影响实体权利
- 中：可能导致部分权利受限或增加举证难度
- 高：可能导致主要权利丧失或重大不利裁判
- 阻断：直接导致合同无效、诉求被驳回、权利消灭

**商业/运营影响轴**：对工程进度、成本、商业关系的实际影响
- 低：影响金额 < 合同价的1%，不影响工期
- 中：影响金额 1%-5%，可能造成局部工期延误
- 高：影响金额 5%-10%，可能造成重大工期延误
- 阻断：影响金额 > 10%，可能导致项目停滞

### 3.2 严重性词汇映射

分析结论中的风险等级标记必须统一：

| 本文档用语 | 含义 | 适用标准 |
|-----------|------|---------|
| 监控 | 风险存在但不影响当前决策，定期复查即可 | 法律风险=低，商业影响=低 |
| 常规 | 属于施工合同常见风险，按标准流程处理 | 法律风险=低/中，商业影响=低/中 |
| 优先 | 需要重点关注并在合理期限内采取措施 | 法律风险=高 或 商业影响=高 |
| 严重 | 必须立即处理，可能对案件走向有决定性影响 | 法律风险=阻断 或 商业影响=阻断 |

### 3.3 风险校准矩阵

```
              法律风险 →
               低      中      高     阻断
商业  低      监控   常规   优先   严重
影响  中      常规   常规   优先   严重
↓     高      优先   优先   严重   严重
     阻断     严重   严重   严重   严重
```

## 四、严格模式护栏

### 4.1 禁止静默补充（三值选择机制）

分析过程中遇到信息不足时，Agent 必须选择以下三种处理方式之一，不得自行猜测填补：

| 选择 | 含义 | 使用场景 |
|------|------|---------|
| **是** | 基于已有信息可以明确判断 | 信息充分、法条明确 |
| **否** | 基于已有信息可以明确排除 | 信息充分、法条明确排除 |
| **需确认** | 信息不足，需要向用户确认或通过检索补充 | 合同未约定、事实不明、法律存在争议 |

**铁律**：不得在 `[需确认]` 状态下给出确定性结论。必须明确标注假设前提。

**输出格式**：
```
> [需确认] 以下分析基于"合同未约定违约金上限"的假设。如合同实际有约定上限条款，以下分析不适用。
> 请确认：合同第X条是否有违约金上限约定？
```

### 4.2 时效触发检查

分析中遇到以下触发条件时，必须主动检查时效：

| 触发条件 | 检查事项 | 依据 |
|---------|---------|------|
| 合同价款争议 | 优先受偿权是否在18个月内行使 | 司法解释一第36条 |
| 质量缺陷争议 | 缺陷责任期/保修期是否届满 | 合同约定 + 法定最低年限 |
| 工程款欠付 | 逐笔分析每期进度款的独立诉讼时效，不得笼统以最后一笔付款为基准 ★v2.0 | 民法典第188-195条；详见 `per-claim-limitation-analysis.md` |
| 工程款欠付 | **禁止仅以最后一笔付款为全部债权时效基准**——每期进度款是独立债权 ★v2.0 | per-claim-limitation-analysis.md |
| 索赔事件 | 合同约定的索赔通知期限是否已过 | 合同具体条款 |
| 裁决/判决 | 申请执行是否在2年内 | 民诉法第250条 |

### 4.3 用户陈述核实

用户提供的履约事实（"发包人拖欠了我们两年"）应当在分析中：
1. 作为**分析假设前提**予以采纳
2. 同时标注 `[用户陈述]` 以示该事实来源于用户而非客观证据
3. 在证据组织模块中提示需要相应证据支撑

### 4.4 目的地检查

输出任何分析结论前，检查：
- 结论是否在"律师审查草稿"的定位范围内（不越界为正式法律意见）
- 是否包含必需的免责声明和验证提示
- 所有法律引用是否已标注来源标签
- 所有 `[需确认]` 标记是否清晰可识别

### 4.5 跨模块严重性下限

多个模块的风险评估出现差异时，采取**最不利推定原则**：
- 任一模块评估为"严重"的风险点，在最终报告中保留"严重"级别
- 不得因其他模块的较低评估而降低该风险等级
- 跨模块矛盾的风险评估须在"最终扫描检查报告"中说明差异原因

## 五、内容分离纪律（诉讼专用）

### 5.1 五组内容分离

在准备诉讼材料时，以下五类内容必须严格分离，不得混合编排：

| 内容类型 | 定义 | 典型产出 |
|---------|------|---------|
| 证据列举 | 逐项列举证据材料的客观信息 | 证据目录（名称/页码/形式/来源） |
| 质证意见 | 对对方证据的三性（真实性/合法性/关联性）和证明力发表意见 | 质证意见书 |
| 证据认定 | 法院对证据的态度预判 | 证据风险评估（内部使用） |
| 查明事实 | 基于可采信证据重构的事实 | 事实陈述/代理词事实部分 |
| 争议焦点 | 双方对事实和法律适用存在的分歧 | 争议焦点摘要 |

### 5.2 分离铁律

1. **证据列举不得包含论证**：证据目录中"证明目的"栏仅陈述该证据直接证明的事实，不写法律结论
2. **质证意见不得预判法院认定**：质证意见仅从己方立场发表，不替代法院的认证判断
3. **事实陈述不得引用未经质证的证据**：代理词/起诉状中的事实陈述必须以可采信证据为基础
4. **争议焦点摘要独立成章**：不在证据分析或事实陈述中混入争议焦点评判

## 六、决策树模式

### 6.1 分析流程中的决策节点

以下典型决策节点必须显式化，不得跳过：

**合同效力判断决策树**：
```
是否取得规划审批？
  ├── 是 → 检查以下：
  │   ├── 承包人是否有资质？→ 否 → 合同无效（司法解释一第1条）
  │   ├── 是否应招标而未招标？→ 是 → 合同无效
  │   └── 是否存在转包/违法分包？→ 是 → 相应合同无效
  └── 否 → 起诉前是否取得？
        ├── 是 → 合同有效
        └── 否 → 合同无效（司法解释一第2条）
```

**利息起算决策树**：
```
合同是否约定付款期限？
  ├── 是 → 约定付款日次日起算
  └── 否 → 以下日期中最先发生者：
        ├── 工程实际交付日
        ├── 提交竣工结算文件日
        └── 起诉日
```

### 6.2 模棱两可时的处理

遇到法律适用模棱两可的情况：
1. 列出两种以上的可能解释
2. 标注每种解释的支持依据 `[法条原文]` 或 `[裁判规则]`
3. 给出倾向性意见并标注 `[需验证]`
4. 明确告知用户不确定性，建议咨询专业律师

## 七、量化风险维度（Quantitative Risk Dimensions）★v2.0

### 7.1 概述

仅使用"严重/优先/常规"三级定性标签不足以支撑客户决策。对每个标注为"严重"或"优先"的风险，**必须**补充以下三个量化维度。

### 7.2 三维量化定义

| 维度 | 定义 | 输出格式 |
|------|------|---------|
| **敞口金额** | 该风险实现后的最大财务损失估算 | 具体金额或金额区间 + 计算基准说明 |
| **时间窗口** | 剩余的可处置时间 | "X天内"/"X周内"/"X个月内"/"已届满"/"无法确定" |
| **可控性** | 通过己方行动降低风险的可能性 | "可控"/"部分可控"/"不可控" + 说明 |

### 7.3 应用示例

```
风险：诉讼时效届满
  敞口金额：影响债权总额约¥58M-¥85M（全部欠付工程款）
  时间窗口：已于2026年1月14日届满（约5个月前）——如无中断证据，已无可处置时间
  可控性：不可控（时效已届满），如存在催款记录则可逆转为可控
```

### 7.4 与双轴标尺的关系

严重/优先/常规定性 + 三维量化 = 完整的风险评估：
- 定性（双轴）回答"这风险有多严重"
- 敞口金额回答"损失有多大"
- 时间窗口回答"还有多少时间"
- 可控性回答"我们能做什么"


## 八、量化敞口计算模板 ★v2.1新增

### 8.1 违约金敞口计算

```
违约金最大敞口 = min(约定违约金总额, 法定调整上限)

# 逾期竣工违约金
约定：逾期天数 × 日违约金标准（元/天）× 逾期天数
法定上限：合同价 × 5%（部分地区参考）或 实际损失的130%
敞口 = min(约定, 法定上限)

# 逾期付款违约金
约定：欠付本金 × 约定年利率 × 逾期天数 / 365
法定上限：欠付本金 × LPR四倍 × 逾期天数 / 365
敞口 = min(约定, LPR四倍)
```

### 8.2 利息敞口计算

```
利息敞口 = Σ(每笔欠付款本金 × 分段LPR × 分段天数 / 365)

多笔欠款示例：
  第1期: ¥2,000,000 × 3.45% × 500天/365 = ¥94,521
  第2期: ¥3,000,000 × 3.35% × 400天/365 = ¥110,137
  第3期: ¥5,000,000 × 3.25% × 300天/365 = ¥133,562
  合计敞口: ¥338,219

注意：
- LPR变动时需分段计算
- 2019.8.19之前用央行贷款基准利率
- 部分付款按"先利息后本金"清偿顺序
```

### 8.3 工期延误敞口计算

```
# 承包人视角 — 逾期违约金敞口
逾期违约金敞口 = 可能逾期天数 × 日违约金标准

# 发包人视角 — 逾期交付损失敞口
损失敞口 = 延期交付导致的额外成本 + 收益损失
  额外成本：另行租赁费用、赶工费等
  收益损失：租金损失、经营利润损失等

# 同期延误下的敞口调整
如双方均有责任 → 敞口 = 总敞口 × 承包人过错比例
```

### 8.4 质量修复敞口估算

```
修复费用敞口 = Σ(缺陷部位 × 修复方案预算)

估算方法（优先级从高到低）：
1. 已有鉴定报告 → 以鉴定造价为准
2. 已有修复合同/报价 → 以合同/报价为准
3. 无具体数据 → 估算 = 缺陷部位合同价 × 修复难度系数
   - 面层修复: 缺陷部位合同价 × 5%-15%
   - 局部结构修复: 缺陷部位合同价 × 15%-30%
   - 大面积/主体结构: 缺陷部位合同价 × 30%-100%

注意：以上估算仅用于风险敞口预判，诉讼中需通过司法鉴定确定精确金额
```


## 九、新增决策树 ★v2.1新增

### 9.1 实际施工人认定决策树

```
是否投入资金、材料、劳动力进行实际施工？
  ├── 否 → 不构成实际施工人（可能是农民工/班组成员/材料商）
  └── 是 → 施工合同是否无效？
        ├── 否 → 不构成实际施工人（为合法承包人）
        └── 是 → 与承包人是否存在劳动关系/内部承包关系？
              ├── 是 → 不构成实际施工人（为内部职务行为）
              └── 否 → 是否参与签订施工合同或实际履行？
                    ├── 否 → 不构成实际施工人
                    └── 是 → ✅ 构成实际施工人
                          ↓
                    能否突破合同相对性向发包人主张？
                    ├── 转包/违法分包（一层）→ ✅ 可以（司法解释一第43条）
                    ├── 挂靠 + 发包人知情 → ✅ 可以（2025征求意见稿）[未生效]
                    ├── 多层转包/违法分包 → ❌ 不可以（仅可向合同相对方主张）
                    └── 挂靠 + 发包人不知情 → ❌ 不可以（仅可向被挂靠人主张）
```

### 9.2 内部承包 vs 挂靠/转包决策树

```
是否有正式劳动合同 + 社保缴纳记录？
  ├── 否 → 挂靠或转包（非内部承包）
  └── 是 → 企业是否对项目进行实质管理？
        ├── 否（仅收取管理费、不派驻人员、不管理资金）→ 名为内部承包实为挂靠/转包
        └── 是 → 工程款是否由企业统一收支？
              ├── 否（款项直接到个人账户）→ 名为内部承包实为挂靠
              └── 是 → 企业是否承担项目盈亏？
                    ├── 否（盈亏由个人自负）→ 名为内部承包实为挂靠
                    └── 是 → ✅ 合法的内部承包关系
```

### 9.3 联合体责任分配决策树

```
争议发生在哪个层面？
  ├── 对发包人 → 联合体各方承担连带责任（法定）
  │     ↓
  │     承担一方可向其他成员内部追偿
  │     （按联合体协议约定比例，无约定按过错/受益比例）
  │
  ├── 对下游分包商/供应商 → 合同是否有明确约定？
  │     ├── 有约定联合体共同/连带责任 → 按约定
  │     └── 无约定 → 遵循合同相对性，仅实际签约成员承担责任
  │
  └── 行政/刑事责任 → 各自承担（不连带）
        （按"责任自担"原则，谁违法谁承担）
```


## 十、谈判策略建议模板 ★v2.1新增

### 10.1 条款谈判通用策略

| 风险等级 | 策略 | 说明 |
|---------|------|------|
| 严重 | 底线条款 — 必须修改 | 不修改可能导致权利丧失或重大损失，宁可不签 |
| 优先 | 竞争条款 — 力争修改 | 有谈判空间时优先争取，可适当让步换对方妥协 |
| 常规 | 让步条款 — 可接受 | 属于行业惯例或影响有限，可接受以换取对方在严重条款上的让步 |
| 监控 | 记录条款 — 不改但记录 | 不改条款本身，但在会议纪要/合同批注中记录己方理解和关切 |

### 10.2 常见条款谈判建议

| 条款 | 承包人建议方案 | 发包人建议方案 |
|------|--------------|--------------|
| 违约金上限 | 增设上限（建议合同价3-5%） | 不设上限或设置较高上限 |
| 审计前置 | 增加最长审计期限（建议3-6个月），逾期视为认可 | 保留审计作为付款条件 |
| 背靠背付款 | 力争删除，或增加最长付款期限上限 | 保留但对分包人透明化 |
| 质保金 | 降低比例（争取1-2%），明确返还节点和逾期利息 | 保持3%，分期返还 |
| 索赔失权 | 增加失权例外条款（2025示范文本19.7条） | 保留严格期限 |
| 情势变更 | 增加材料价格波动超X%时调价的触发机制 | 固定总价不调价，或设置较高触发门槛 |

### 10.3 谈判策略输出格式

```markdown
### 条款XX 谈判策略

**风险等级**：[严重/优先/常规/监控]
**己方立场**：[[X方]]
**条款现状**：[原文摘要]

**谈判目标**：
- 最优结果：[最理想的情况]
- 可接受结果：[底线 — 低于此则建议不接受该条款]
- 交换筹码：[可以用什么条款的让步换对方在此条款的让步]

**法律支撑**：[可引用的法条/案例/行业惯例]
**商业理由**：[可向对方陈述的商业合理性]
```
