## Outcome and runner rule

Playwright owns browser-rendered product behavior: navigation, forms, chat rendering, keyboard interaction, settings persistence and browser media errors. It runs the real standalone core and checksum-pinned modules against the existing local mock backend. Merely calling core RPC does not justify WDIO. WDIO owns an assertion only when it depends on the actual desktop process: real Tauri IPC, launch bearer/URL/relay, OS/window or deep-link entry, notification plugin permissions, process restart, PTT or other host orchestration. Keep the existing Wry driver; do not restore CEF/CDP assumptions.

A mixed spec is split by assertions, not renamed wholesale. Move every distinct SPA assertion to Playwright and prove it runs before deleting its native source. Retain only the host-dependent assertions on desktop. No new backend-only browser tests are needed to justify deletion; existing Rust wire tests remain authoritative for module/controller behavior. Do not delete a stronger native test merely because its browser twin has the same name.

The documented basename allowlist will contain exactly these five mixed files, with the restricted native responsibilities below:

| Basename                           | Native assertions retained                                                                                                   | Playwright responsibility                                                     |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `smoke.spec.ts`                    | Live WebDriver session, mapped native window/app chrome, nonempty main webview and normal embedded-core startup              | Browser root/chrome, standalone core bootstrap URL/token and RPC reachability |
| `login-flow.spec.ts`               | Actual desktop window/process and deep-link token handling, including expired/invalid and bypass cases                       | Web callback entry, token/profile outcome, browser bypass and onboarding      |

Both `core-port-conflict-recovery` copies only assert normal startup: move their useful startup assertions to the respective smoke cases, delete both files and record that neither established occupied-port recovery. Do not claim new port-conflict coverage.

This plan does not move the 24 non-twin native files wholesale. They have no losing twin in this issue. Keep them discoverable, preserve their existing skips and do not call all their generic SPA behavior a desktop requirement. A future new test must follow the rule above. Cross-runner renamed full-flow duplication is forbidden even if basename intersection becomes empty.
